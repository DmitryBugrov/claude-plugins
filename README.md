# context-guard

Плагин Claude Code для контроля размера контекста сессии. Каждый ход и каждый вызов инструмента перечитывают весь
контекст, поэтому при его росте плагин просит модель записать передачу сессии (состояние, решения, открытые
вопросы, следующие шаги) и предлагает сделать `/clear`. После `/clear` записанный раздел подгружается в новую сессию.

## Что делает

- **PostToolUse** — мягкий сигнал внутри хода (`additionalContext`), когда контекст достиг порога; ход не блокируется.
  Вызовы саб-агентов игнорируются.
- **Stop** — если сигнал не помог или хода с инструментами не было, при остановке блокирует ход с просьбой записать
  передачу; после записи пользователь получает сообщение с рекомендацией `/clear`.
- **SessionStart** (`startup|resume|clear|compact`) — после сжатия контекста напоминает про передачу;
  подгружает последний раздел (до 40 строк) файла передачи; чистит состояние сессий старше 7 дней.

## Как пользоваться

Типичный цикл:

1. Контекст достигает порога — в ходе приходит сигнал (или Stop блокирует остановку).
2. Модель дописывает в файл передачи новый раздел `## ГГГГ-ММ-ДД ЧЧ:ММ`; открытые пункты прошлого раздела
   переносятся в новый или явно закрываются.
3. Пользователь видит сообщение «⚠ /clear» и делает `/clear`.
   Если до `/clear` пользователь пишет ещё сообщения, передача обновляется повторно — не раньше, чем контекст
   вырастет на 25 тыс.
4. В новой сессии SessionStart подгружает последний раздел, и работа продолжается с сохранённого состояния.

Фоновые задачи: если при рекомендации `/clear` работают только фоновые агенты, их отчёты дойдут и после `/clear`
(проверено вживую). При прочих фоновых задачах (например, Bash) сообщение просит дождаться их завершения.

## Требования

- Claude Code версии 2.1.x: формат журнала сессий привязан к версии Claude Code, плагин объявить требование
  к версии не может.
- Windows: Git for Windows и Python 3.9+, доступный в `PATH` как `python`.
- macOS: `python3` 3.9+ — Xcode Command Line Tools или Homebrew. Без Command Line Tools системный `python3` —
  заглушка установщика, а не интерпретатор.
- Linux: `python3` 3.9+.

Без подходящего Python хук выдаёт ошибку на каждом инструменте.

## Установка

```
claude plugin marketplace add DmitryBugrov/claude-plugins
claude plugin install context-guard@team-claude-tools --scope user
```

Плагин применяется в новых сессиях и после `/reload-plugins`. Если маркетплейс объявлен в настройках проекта,
установка плагина всё равно отдельная и выполняется по желанию каждого участника.

## Настройки

Два значения `userConfig` задаются при установке или позже:

```
claude plugin install context-guard@team-claude-tools --scope user --config threshold_tokens=120000
claude plugin configure context-guard@team-claude-tools
```

`claude plugin configure` показывает опции и какие из них не заданы; сохранить значения можно, передав JSON-объект
из строк в stdin с флагом `--values-stdin`.

| Ключ | Умолчание | Смысл |
| --- | --- | --- |
| `threshold_tokens` | 170000 | порог размера контекста, при достижении которого просится передача |
| `repeat_step_tokens` | 50000 | повторный сигнал — после роста контекста ещё на столько токенов |

Хуки читают значения из `CLAUDE_PLUGIN_OPTION_THRESHOLD_TOKENS` и `CLAUDE_PLUGIN_OPTION_REPEAT_STEP_TOKENS`;
отсутствующее или некорректное значение (не положительное целое) заменяется умолчанием без предупреждения.
Порог выше 180000 допустим, но SessionStart при каждом старте сессии выводит предупреждение: это близко
к автосжатию контекста. Отдельного выключателя нет: плагин отключается командой
`claude plugin disable context-guard@team-claude-tools`.

## Куда пишется передача

По умолчанию — в собственный файл `${CLAUDE_PLUGIN_DATA}/handoff/<имя каталога журнала>.md` в каталоге данных
плагина, вне репозитория проекта. Раздел добавляется в конец файла; время подставляет плагин (время сигнала),
модель его не придумывает. Две параллельные сессии одного проекта пишут в один файл.

Внешний поставщик передачи может перенаправить запись: если в каталоге журнала сессии
(`~/.claude/projects/<проект>/`) лежит дескриптор `handoff-provider.json`, передача пишется по нему. Схема 1:

```json
{
  "schema": 1,
  "provider": "example",
  "handoff_path": "/абсолютный/путь/к/handoff.md",
  "template": "Формат раздела: ветка, состояние, сделано, вопросы, шаги",
  "loads_on_start": true
}
```

- `handoff_path` — файл, в который модель пишет передачу;
- `template` — текст шаблона раздела, он попадает в просьбу к модели;
- `loads_on_start: true` — раздел при старте загружает сам поставщик, плагин этого не делает.

Неизвестная схема или битый дескриптор — плагин молчит. Чтобы вернуться к собственному файлу, удалите дескриптор.
Запись в каталог данных плагина (`~/.claude/plugins/data/`) может потребовать разрешения Claude Code; при отказе
добавьте этот каталог в `additionalDirectories` настроек.

## Обновление

Версия берётся из `plugin.json` (`version`). Автообновление сторонних маркетплейсов по умолчанию выключено:

```
claude plugin marketplace update team-claude-tools
claude plugin update context-guard@team-claude-tools
```

Авторам: при каждом выпуске версию нужно поднимать, иначе участники не получат новые коммиты.

## Удаление

```
claude plugin uninstall context-guard@team-claude-tools --keep-data
claude plugin marketplace remove team-claude-tools
```

С `--keep-data` сохраняются файлы передач (`handoff/`) и состояние; без флага каталог данных удаляется вместе
с плагином. Потеря состояния сессий безвредна: самое большее один лишний сигнал в открытых сессиях.

## Разработка

```
python -m pytest plugins/context-guard/tests -q   # тесты, из корня репозитория
claude plugin validate .                          # маркетплейс
claude plugin validate plugins/context-guard      # плагин
```

Тесты запускают хуки подпроцессом (`python scripts/run.py <событие>`) с `CLAUDE_PLUGIN_DATA` во временном
каталоге. CI (`.github/workflows/test.yml`) гоняет их на Linux, Windows и macOS с Python 3.9 и 3.12.
